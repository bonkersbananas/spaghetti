# 0059. A model's original opens in Bambu Studio too, an .stl wrapped in a 3MF on the way

Status: Accepted (extends [0058](0058-open-in-bambu-studio-by-a-signed-link.md))

**Decision:** "Open in Bambu Studio" can open a model's original as well as its sliced file (Carl Oscar, Nov 14: "could sometimes be useful"). A sliced model has two things to open, so its action opens a small menu of them, the sliced file first ("Sliced file · Ready to print", "Original model · To slice or tweak"); anything with one thing to open (an unsliced model, a slicer file) opens it with one tap, as before. The original `.3mf` opens as it is. An `.stl` is wrapped in a minimal 3MF as it is downloaded, because Bambu Studio imports only `.3mf` by address, so unsliced `.stl` models get the action too.

- **The link is unchanged:** `part: "file"` already named the original; for an `.stl` the Worker converts on the way and the link's last segment ends in `.3mf` (`Mount-v2.stl` → `Mount-v2.3mf`). No new part, no stored copy, nothing to clean up.
- **In the Worker, streamed:** the STL is read from R2 in pieces and written as 3MF XML (binary and ASCII STL; three vertices a triangle, unshared, which Bambu Studio merges on loading; triangles with a coordinate that isn't a number are dropped) into a ZIP whose big entry is deflated by the platform's `CompressionStream` and closed with a data descriptor. Memory stays flat whatever the size; the answer has no `Content-Length`. The CRC-32 and the ZIP's headers are written by hand (`src/shared/threemf/stl-wrap.ts`).
- **A size limit, not a browser fallback:** the XML costs Worker CPU time, about 150 ms a MB in the worst case (random triangles, measured in Node), so an `.stl` over 32 MB (`STL_WRAP_MAX_BYTES`) isn't offered: its original can't be opened from here, and a sliced one still opens its sliced file. The files the app takes go up to 250 MB; converting those in the browser (and handing Bambu Studio a stored copy) was left out as more machinery than the need shows. Say if it is wanted.
- **Bambu Studio's notice:** a 3MF that isn't from Bambu Lab loads with "The 3mf is not from Bambu Lab, load geometry data and color data only" (what we want of an original). The wrapped file's `Application` isn't `BambuStudio-…` on purpose (see 0058's addendum: that is for sliced files only).
- **Phones and tablets** still see nothing (0058).
