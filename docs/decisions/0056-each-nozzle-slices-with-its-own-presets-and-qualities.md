# 0056. Each nozzle slices with Bambu's own presets, its qualities keep their names, and every slice is for the main nozzle

Status: Accepted

**Decision:** Spaghetti slices for every nozzle size the X2D takes (0.2, 0.4, 0.6 and 0.8 mm) with Bambu's own X2D presets for it, in the engine's release since `slicer-v2` (`scripts/slicer/resolve-presets.mjs`): its machine, every process Bambu has for it, and a filament per material. The named qualities are each nozzle's own (`qualitiesFor` in `shared/slicing/settings.ts`): Fine and Standard are Bambu's processes (0.2 mm: Fine 0.08 High Quality, Standard 0.10 Standard, Draft 0.12 Balanced; 0.6 mm: 0.18 Balanced and 0.30 Standard; 0.8 mm: 0.24 Balanced and 0.40 Standard), Draft and Extra draft above Bambu's coarsest process are that process at a taller layer, Extra draft the tallest the nozzle prints (seven tenths of its width: 0.14, 0.28, 0.42, 0.56 mm). The settings keep a layer height in millimetres (decision 0047's shape); when the nozzle changes (`withNozzle`), a named height moves to the same name on the new nozzle (a model at 0.20 mm, Standard, slices at 0.10 mm for the 0.2 mm nozzle, and back), and a height without a name keeps its share of the nozzle's width (0.16 mm on the 0.4 mm is 0.08 mm on the 0.2 mm), within what the new nozzle prints.

Which nozzle: every slice is for the main nozzle (the direct-drive one on the left), at the size fitted there, because the engine prints every slice with it; nothing offers the auxiliary nozzle. When the two nozzles fitted are the same size, nothing new shows. When they differ, "Slice with…" and the Printer page's slicing defaults show one line where a choice would be ("Slices for the main nozzle (0.4 mm) · to slice for the 0.2 mm, fit it as the main nozzle."): fitting the 0.2 mm as the main nozzle then slices everything for it. New models always slice for the main nozzle; the defaults keep the nozzle their layer height was set for, so it keeps its name there. "More" still offers any of the four sizes, for slicing ahead of a swap, and a slice for a size the main nozzle doesn't have says so plainly: on the card ("Sliced for a 0.6 mm nozzle; the main nozzle has a 0.4 mm.", with a "Slice for the 0.4 mm" button), under the sheet's Filament and in More. "Print it" on a twist shows the same card, and the attempt it starts says "The main nozzle fitted is 0.4 mm." from the file's nozzle size. The card's settings row and its line name a nozzle that isn't the 0.4 mm. A filament Bambu has no preset for on a nozzle (the 0.2 mm has no carbon fibre, TPU, PA, PP or PCTG) slices with its nearest kin (PETG-CF as PETG, the others as PLA) and the sheet, the card and the story say so ("No 0.2 mm preset for PETG-CF: sliced as PETG."); silk is Bambu's own silk PLA there.

**Why:** Carl Oscar bought 0.2 mm nozzles (Nov 13) and asked for the other nozzle heads to be supported. Bambu's presets are tuned per nozzle (line widths, speeds, flow), so a 0.2 mm slice made from the 0.4 mm's presets would be wrong in every line; a quality name ("Standard") is what people mean, not a number that only fits one nozzle. A first version offered the auxiliary nozzle as a choice; Carl Oscar ruled it out (Nov 13): the engine doesn't take a filament's nozzle (`filament_map`) and OrcaSlicer refuses two nozzle sizes in one slice, so that file would print 0.22 mm lines through the main 0.4 mm nozzle (or trip the printer's nozzle check). A choice that makes a file for a nozzle it won't print with isn't offered.

**Consequences:**

- Printing with the second nozzle (a 0.2 mm in the auxiliary beside the 0.4 mm) comes with Spaghetti's own slicer (session #923 ports Orca's second-nozzle printing there), not with this engine.
- `presets.json` grew from 235 kB to 630 kB (41 kB gzipped), fetched once per engine version, only to slice.
- The `nozzle` problem (no presets for a nozzle) remains for an engine without them; the Rust slicer (session #775) adds the same nozzles on its side.
