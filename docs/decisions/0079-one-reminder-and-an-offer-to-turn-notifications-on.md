# 0079. A print still unanswered an hour later gets one reminder, and whoever has no push is offered it once

Status: Accepted (extends [0016](0016-web-push-nudges.md))

**Decision:** The weekend's read (Nov 19-23) showed 3 of 9 prints answered more than an hour after they ended, and only one of the two people with push on. Carl Oscar chose "Yes, both", so:

- **The reminder.** When a print's first nudge went out an hour ago and the attempt still has no outcome, the Worker sends one more push to **everyone with a push subscription**, whoever started the print (the other person hears "how did Sam's print go?"). Once per attempt and person (`push_reminders`, claimed before sending like `push_nudges`, released if nothing got through so the next run retries), never a third. The same quiet hours (22:00 to 07:00 per device; it waits for the morning) and the same twelve-hour window from the print's end as the nudge; an outcome set meanwhile cancels it. Its words: title "Tugboat is still waiting", body "When you have a moment: how did it go?", with the same answer buttons and the same notification tag, so it replaces the first notification instead of stacking under it. It is `sendReminders`, run by the same cron as `sendNudges`.
- **The offer.** A person with no push subscription on any device is offered notifications once, as a small card at the bottom of Today (on a phone, at the bottom of the Journal's Now block, as phones have no Today): what they would hear about (a print that is done and waiting for its answer), "Turn on" (the same subscribe flow as the Notifications sheet, the browser asks for permission then) and "Not now". "Not now" is for good and is kept on the server (`users.push_offer_dismissed_at`), so no other device asks again; the card also goes by itself once any device has push. It is drawn only where this device can subscribe: not on iPhone or iPad Safari outside the Home Screen app (where the Notifications sheet already says to add Spaghetti to the Home Screen), not in a browser without web push, not when the permission is blocked, not on a server without a push key. The card sits last and appears about a second after the screen, so it never pushes a print waiting for its answer down and its code stays out of the first load.

**Why a table of its own:** `push_nudges` is keyed by attempt and person and only holds who got the first nudge; the reminder also goes to the person who didn't, so it has its own rows. **Left out:** a third reminder, an escalating tone, a setting for either (turning push on is the consent), and offering again after "Not now".
