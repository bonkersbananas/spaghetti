# 0075. A public link shows one idea, build or twist, read-only, to anyone who has it

Status: Accepted

**Decision:** Either person can give an idea, a build or a twist a public link, on purpose and one at a time, from the share button on its page. Someone who isn't signed in opens `https://spaghetti.day/s/<token>` and sees that one thing, read-only, on a page of its own: no app around it, no script, photos first. Nothing is shared by default; the private link (the page itself, for the two people) stays the share button's other choice. The share button shows a basil globe while a link is live; the panel copies it again (phones: the system share sheet) and stops it at once, with Undo bringing back the same address. Sharing again later makes a new token.

**What a guest sees:** the title, the photos (large, the cover first), the note with only its http(s) addresses as links, and the model's page as a card (MakerWorld, Printables… with the title, designer and licence the draft read). A build adds how it went (its attempts' outcomes as a trail, the time and filament spent) and each attempt: outcome, date, photos, note, what changed since the one before, what went wrong or well, and the settings to print it with (printer, filament, nozzle, profile, layer height, infill, walls, supports, brim, plate, temperatures) where the build page lists them. A twist adds its source, what we changed and, when it has a recipe, how we print it. **Hidden:** comments, reactions, Up next, wishlists, who it is for, the people (no names, no faces, no who-did-what: the page says what was made, as the landing page does), anything Claude wrote about it (the coach, naming, photo reads), parts, every other thing, and every file: no downloads of models or sliced files, which can be someone else's licensed model; the source page is linked instead. The page is built from an allow-list (`worker/guest/view.ts`): a field added to items later stays private until someone adds it there.

**The link:** `/s/<token>`, the token 18 random bytes (144 bits) in base64url. `shares` keeps the token, so either person can copy it again, and its SHA-256, which is what a link is looked up by: the time a lookup takes says nothing about the token. One live link per thing (a partial unique index). It ends when it is stopped (`revoked_at`) or the thing is deleted; undoing the delete brings it back with the thing. An unknown, malformed, stopped or deleted link all get the same 404 page, "This isn't shared anymore". The routes are GET and HEAD only and write nothing; every other method is a 405. The token opens nothing under `/api`. Making, listing and stopping links is for people only (`/api/shares`): no agent scope reaches them, and their changes are private to the people's own feed (never an agent's or a webhook).

**Photos:** only through the token (`/s/<token>/photos/<id>/thumb|large`; the bucket stays private), only the thing's own live photos (not a deleted attempt's; for a twist, only the photo it leads with), sized for the page with `srcset`. A photo is served only if its stored bytes carry no EXIF, XMP or IPTC (`shared/photo-metadata.ts` reads the JPEG segments or WebP chunks, and looks for an EXIF header or XMP packet anywhere): a browser-resized photo has none, but one stored as it came (an agent's or the bridge's, `needs_resize`) may hold a GPS position, so it is neither listed nor served, and neither is one that slipped through another way. `Cache-Control: private, max-age=300` keeps photos out of shared caches, so they stop with the link; the page itself is `private, no-store`.

**The page:** rendered by the Worker with hono/jsx, which escapes every text and attribute, into `guest.html`, styled by `src/guest/guest.css` on the app's tokens and fonts (light only, like the landing page), so a guest downloads none of the app's code and the app's first load doesn't change. Link previews (Open Graph and Twitter: title, a line of the note, the cover photo) are written without JavaScript. Headers: `X-Robots-Tag: noindex` (and the robots meta), `Referrer-Policy: no-referrer` (and `rel=noreferrer` on links out), no framing, and a policy with no script at all (`default-src 'none'`). Someone signed in on that browser is sent to the thing's own page in the app; the service worker leaves `/s/` to the network.

**Why:** xixa (Nov 21): "I want to be able to share an idea, build or twist to a not logged in user. They should not be able to start a build or control anything. Just look. Make it useful and nice." The workspace stays private ([0002](0002-two-people-no-sign-up.md)): a public link is a capability for one thing, made deliberately, never an account or a role.

**Consequences:** whoever holds a link can look at that thing until it is stopped, and what they saw (and what a chat app's preview fetched) can't be taken back. People's display names are left out; showing them would be a new decision. A build of a twist doesn't show the twist, and plate pictures aren't shown (a thing with no photo leads with its note). Revoked rows stay (they are the Undo) and go with their thing at the purge. Revisit if links should expire on their own, or if someone wants a list of everything shared.
