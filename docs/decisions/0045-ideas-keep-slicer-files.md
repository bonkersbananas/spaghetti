# 0045. An idea keeps slicer files, and they stay with it as a build

Status: Accepted

**Decision:** An idea (and the build it grows into) can hold any number of `.3mf` and `.gcode.3mf` files (at most 20), picked with "Add a file" or dropped on the idea page on desktop. They are stored like an attempt's file: read in the browser (decision [0013](0013-bambu-studio-and-orca-files-only.md), Bambu Studio and Orca only), the same 25 MB cap, R2 keys `files/<id>/file` and `/thumb`, served at `/api/files/:id`, opened in 3D from the plate picture ([0036](0036-the-3d-view-reads-the-slicer-file-in-the-browser.md)). The rows live in `item_files` (one table beside `attempt_files`, with the same columns and `item_id` for `attempt_id`); `GET /api/files/:id` looks in both. The file belongs to the item, so starting a build changes nothing about it, and the first attempt's sheet offers each file ("Kept with the idea") as a one-tap way to fill the attempt from it; that copies the file onto the attempt, which is what makes it the attempt's own. An idea with a file counts as having a model: the sticker reads "3MF" and the "Has a model" filter includes it, after any model link (a link wins).

**Why:** Carl Oscar asked to keep slicer files with ideas while working on them. One mechanism with the attempt's file (same reader, fields, keys, viewer, purge) is cheaper than a second one, and keeping the file on the item means nothing has to be moved when an idea becomes a build.

**Consequences:** Adding and removing needs a connection (offline, saved things are read-only, [0005](0005-offline-read-only-with-outbox.md)), so files do not go through the outbox: they show at once and a refusal takes them off again. Agents may add one with the `capture` or `attempts` scope (`PUT /api/items/:id/files/:fileId`); removing and restoring are for people. MCP `get_build` lists the files, but there is no tool to add one: an agent cannot read the plate or the settings, so the file would say nothing. The share target still takes photos only. Twists ([0043](0043-twists-are-models-we-print-our-own-way.md)) should keep their source file through the same pieces (the multipart fields, `fileKey`, `/api/files/:id`, `FileCard`) rather than a third mechanism; they may add a plain `.stl` kind in their own record.
