# 0046. Models are sliced in the browser, with OrcaSlicer's own engine

Status: Accepted

**Decision:** Wherever a slicer file goes (an idea's or build's files, an attempt's file, a drop on those pages), Spaghetti also takes an `.stl` or a plain `.3mf` (a project with no G-code), keeps it as it is, and slices it into a `.gcode.3mf` in the browser: OrcaSlicer's slicing core compiled to WebAssembly (the [Muon3D Slicer Engine](https://github.com/Muon-3D/muon3d-slicer-engine), its single-threaded build, built and released by our own workflow, [slicer.md](../slicer.md)), run in a Web Worker, never in the first load. Such a file is one row of `item_files` or `attempt_files` with `kind` "model" (a slicer's own file is "slicer"): the original is its file (`files/<id>/file`, up to 50 MB), the sliced `.gcode.3mf` a second part of the same row (`files/<id>/sliced`, up to 25 MB, sent with `PUT /api/files/:id/sliced`), and the row's `slice` says how it went: sliced (with the settings it used) or failed (with why). The plate picture is drawn in the browser too, so the card, the estimate, the filaments and the 3D view work as they do for a slicer's file. The defaults live in `shared/slicing/defaults.ts`: the X2D with its 0.4 mm nozzle, OrcaSlicer's 0.20 mm Standard and Bambu PLA Basic presets, the Textured PEI plate, supports off, everything on plate 1 laid out by us; a `.3mf` made for the X2D is sliced with its own settings, one made for another printer keeps its layer height, walls, infill and supports. Once sliced, the card leads with the print ("About 36 min · 10.6 g") and says "Sliced by Spaghetti · PLA · 0.2 mm layers"; its details say it in plain words ("Sliced here with the X2D's usual settings") and link to the engine's source. An idea with no photo takes the newest model or slicer file's plate picture as its cover, until a photo comes.

**Why:** Carl Oscar asked (Nov 13) to drop a generic `.stl` or `.3mf` and see it as a print, sliced "the same way as OrcaSlicer". The proposal ([pull request #205](https://github.com/bonkersbananas/spaghetti/pull/205)) measured the engine against the native OrcaSlicer 2.5.0: the same layers and filament, estimates within 0.6 %, 2 to 9 s per real model in Chromium and WebKit. The browser is the only place this can run without a server of our own: the Worker can't run native code ([0001](0001-cloudflare-workers-d1-r2.md)), and slicing must not depend on a Bambu service or the Mac bridge ([0003](0003-no-bambu-dependency.md), [0010](0010-optional-read-only-printer-bridge.md)). One row with two parts means Remove with Undo, the change feed and the purge work on one thing, and the link between a model and its slice can't break.

**Consequences:**

- Slicing is a job on the device that added the file, one at a time: it goes on through page changes and stops with the tab, and then the card offers "Slice it" to whoever opens it next. A model too large for the plate offers "Scale to N% and slice" (a uniform scale with a small margin, through `shared/mesh.ts`, the same pure mesh functions as Twists' "fit to N mm"); the original is kept as it was. Floating parts are a caution with "Slice with supports".
- A model with no filament colours of its own (any `.stl`) is sliced with a stand-in filament: Bambu PLA Basic in OrcaSlicer's default colour. That colour is only for the pictures; what the slice tells an attempt is the material and the grams, and the attempt keeps its own filament (a spool picked, or the last attempt's).
- A failure is one short sentence on the card, kept on the row (`slice.problem`), except when the engine couldn't load (that is this device's connection, not the file's). A phone that runs out of memory says so honestly, and a laptop or desktop that later shows the file slices it by itself.
- Agents see models and how they were sliced (`get_build` lists the files, the API returns `kind` and `slice`), but they can't slice: there is no MCP tool for it, and `PUT /api/files/:id/sliced` is for people.
- The engine is AGPL-3.0, like OrcaSlicer. It stays a separate program: built from its own source by its own workflow, served from `/slicer/<version>/` with its LICENSE, NOTICE and SOURCE, started by URL and spoken to with messages, never bundled into the app's code; the release carries its Corresponding Source and the app links to it.
- A faster slicer (native, or our own) can replace the engine behind `sliceModel(file)` later without changing the rows, the API or the cards.
