# 0074. The bridge listens to the printer in cloud mode; LAN Only with Developer mode is the fallback

Status: Accepted (Carl Oscar asked for it on Nov 21, 2026; see [docs/bridge.md](../bridge.md))

**Decision:** the bridge is set up with the X2D in its normal cloud mode: LAN Only mode off, Developer mode off, and **LAN Only Liveview** on for the camera. It reads the printer's reports over its local MQTT service with the access code, its SD card or USB drive over FTPS, and one camera frame, and sends only the status request `pushall`. If the printer refuses `pushall` (an error answer, or the connection dropped right after it twice in a row) the bridge stops asking and only listens. Files and the camera are optional: without them a print is still logged, without the printer's copy of its file or a photo. `spaghetti-bridge check` reports each channel on its own line, so one run on the printer says what works in its mode. LAN Only with Developer mode stays documented as the fallback, for a printer that doesn't talk to local programs in cloud mode.

**Why:** Carl Oscar wants Bambu Handy, cloud printing and remote monitoring to keep working. Bambu's authorization firmware (announced Jan 16, 2025, standard on later models) restricts *commands* but says status push over MQTT stays open, and ha-bambulab reads cloud-mode printers (H2D, X2D listed) locally this way. Cloud mode is also the safer mode for a read-only bridge: there the printer refuses unsigned commands itself. Developer mode turns that check off, so the printer takes unsigned commands from anything on the network that has the access code.

**Consequences:** "read-only" is proven by tests (`test/bridge/read-only.test.ts`): the bridge's one publish goes through a guard that throws for anything but `pushall` on the printer's request topic, and the bridge's source has no FTP call that writes, deletes or renames. Whether an X2D in cloud mode answers `pushall` and serves FTPS was not confirmed by any source; the first `check` on Carl Oscar's printer settles it. Bambu's cloud MQTT (a Bambu account) would also deliver reports but stays out ([0003](0003-no-bambu-dependency.md)).
