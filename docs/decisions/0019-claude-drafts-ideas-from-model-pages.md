# 0019. Claude drafts an idea from a model page, in the background, only into empty fields

Status: Accepted

**Decision:** When a capture is just a MakerWorld, Printables or Thingiverse link, or someone taps "Draft from this page" on an idea with one, Claude (`claude-opus-5-5` through the official `@anthropic-ai/sdk`) reads the page and drafts the idea: a title, a short note in our voice, the designer, license, suggested material, plate and settings, and up to four of the model's pictures. The first picture becomes the cover.

**How it stays calm:**
- Capture never waits. The idea is saved with its link at once; the draft is a row of its own (`item_drafts`) that shows "Reading the page…" and fills in afterwards. The other person sees it through the change feed.
- It only fills what is empty (a title that is empty, a note that is only links, an idea with no photos), and each write is conditional in the database too. What it wrote is marked "Drafted by Claude" for as long as the text is still its own, with Undo (also a toast on the device that has the idea open). Designer, license and the settings it found are kept apart from the note, as "From the page".
- It fails quietly: a page that can't be read, a refusal, a timeout or the day's cap leave the idea as captured, with one line and a retry.
- Without `ANTHROPIC_API_KEY` nothing about it shows (`GET /api/features`). People only: a signed-in person, or a sharing token whose only scope is `capture` (the iOS Shortcut), never an agent with more scopes (MCP). 30 calls a day for the workspace.

**Who reads the page (changed after the first real use):** Anthropic's server-side web fetch is turned away by MakerWorld (`url_not_accessible`), while a Worker's own fetch is not (the link cards read it). So the Worker fetches the page itself (`worker/draft/page.ts`: only the three sites, https, redirects checked to stay on them, DNS checked public, 3 MB and 10 seconds), takes what the page states plainly (`shared/model-page.ts`: title, designer, license, picture URLs, and for MakerWorld the print profiles, from the Next.js `__NEXT_DATA__`; for the others the og: tags and JSON-LD) and gives Claude that text as data to write the note and suggest material, plate and settings. Title, designer, license and pictures are the page's, not Claude's. Anthropic's web fetch (`web_fetch_20260209`, `allowed_domains` the three sites) stays as the fallback when the Worker can't get or find anything in the page. Printables answers Cloudflare Workers with a bot challenge (403) and throttles its API, so for now Printables links go through that fallback. Each run records which path it took (`source`) and the Worker fetch's HTTP status in `draft_runs.detail`.

**A title that came with a share isn't the person's:** sharing a page (iPhone Shortcut, Web Share Target, bookmarklet) brings the page's own title along. A capture of a model link plus such a title still drafts by itself, and the draft's title may replace the shared one while it is still exactly that (it is kept as `item_drafts.shared_title`, and Undo gives it back). A title a person typed, before or after, is never replaced; a capture made by an agent with more than the `capture` scope never starts a draft.

**Pictures:** MakerWorld keeps its pictures as large PNGs, which the Worker can't store (JPEG and WebP only, decision 0004). Its image host converts on request, so the Worker asks for a 1600 px WebP (`?x-oss-process=image/resize,w_1600/format,webp`). Every run records what happened to the pictures in `draft_runs.detail.pictures` (found, stored, and a short reason for each one refused). A drafted idea without pictures offers "Get the pictures", which tries again (it isn't a Claude call and doesn't count towards the day's cap).

**Safety:** the Worker never fetches an arbitrary page for this: only hosts of the three sites. The page's text is treated as data, and the answer is constrained to a JSON schema (`output_config.format`). Pictures are downloaded by the Worker only from the sites' image hosts (`src/shared/model-links.ts`), redirects not followed, and stored `needsResize` for a browser to make the thumbnails ([0004](0004-photos-resized-in-the-browser.md)). The request carries no personal details, only the link.

**Why the browser keeps a request open:** an Opus call that fetches a page can take longer than the 30 seconds `waitUntil` allows after a response. So the browser that saved the idea asks `POST /api/items/:id/draft` and the Worker does the call inside that request (no wall-clock limit while the client waits, the same on the deployed Worker and on workerd locally). Anything else that starts a draft (the capture endpoint for the Shortcut and bookmarklet) uses `waitUntil`; and the job row is the fallback for both: the 5-minute cron picks up any draft nobody has worked on for four minutes, twice at most, then marks it timed out. Workers Queues or Durable Objects would work too, but need a binding that the local container doesn't have.

**Left out:** server-side refusal fallbacks (a refusal is shown as a failed draft with a retry); reading a print from a photo (the second roadmap item); an `import_idea` MCP tool.
