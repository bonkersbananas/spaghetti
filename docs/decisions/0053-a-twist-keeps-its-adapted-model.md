# 0053. A twist keeps its adapted model, and prints from it

Status: Accepted

**Decision:** "Adapt an STL" on a twist's page keeps its result with the twist as the twist's own **model**: a row of `twist_files` (a sibling of `item_files` and `attempt_files` with the same columns and R2 keys, `files/<id>/…`), `kind` "model", served at `/api/files/:id` and sliced in the browser exactly as an idea's model is ([0046](0046-models-are-sliced-in-the-browser.md)): on save, with the workspace's slicing defaults ([0051](0051-slicing-defaults-live-on-the-printer-page-recipes-keep-slices.md)), and then with "Slice with…", re-slice and Undo ([0049](0049-a-model-keeps-its-settings-and-one-slice-to-undo.md)), the settings kept on the model. It is named after the source and what changed ("fusilli-knob, 110 %.stl"); the source file is never touched, and Download stays beside "Keep with the twist". A twist keeps one model at a time: a new one takes the place of the one before (which is soft-deleted, as a removal is). The twist page shows it as the model card ideas and builds show, its plate picture is the twist's cover (page and card) while the twist has no photo of its own, and "Print it" / "Print it again" starts a build whose first attempt is printing and carries the sliced `.gcode.3mf` as its slicer file; a twist without a sliced model starts the empty build it always did.

**Why:** a twist is "a model we print our own way", and the app already slices, shows and prints models; the adapted STL was thrown away after the download. [0045](0045-ideas-keep-slicer-files.md) wanted twists' files to reuse the item-file pieces, and they do (same reader, fields, keys, serving, card and slicing jobs); only the owner differs.

**Why not `item_files`:** its `item_id` is a required foreign key to `items`, and a twist is not an item (it may come from no idea at all). Making the column optional means rebuilding a table that holds every kept file; a sibling table with the same shape is cheaper and keeps the existing ones untouched. The cost is a third branch in `liveFile` (`routes/files.ts`), where a twist's file writes a `twist` change (the twist's page and list refetch) instead of a `file` change with an item.

**Consequences:** `Twist.model` in the API carries the file as an idea's `files` do; `PUT/DELETE /api/twists/:id/file/:fileId` and `…/restore` are for people only (agents don't add models to twists, as with ideas). A twist's files are purged with it. Twists never had a "result file" given to them (the proposal's `file_id` was not built), so there is nothing else to keep showing. The first attempt "Print it" starts is left as "Still printing", the way "Still printing" in the attempt sheet does, because pressing Print it is starting a print; it can be removed with its Undo like any attempt.
